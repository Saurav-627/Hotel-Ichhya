1. Executive Summary & Platform Architecture

The Hotel Ichchha Platform is a luxury hotel management, online reservation, and guest hospitality platform engineered specifically for Hotel Ichchha, a 5-star resort and convention center located in Simara, Bara, Nepal.

The platform features an intuitive, luxury user interface built with customized theme tokens (Light, Dark, Luxury Gold, and Festival), a real-time availability and dynamic pricing engine, integrated multi-currency support (NPR, USD, INR, EUR, GBP), and multi-gateway checkout pipelines covering both domestic Nepali wallets (eSewa, Khalti) and international credit cards (Stripe).

4. Database Schema & Data Model Architecture

The platform schema enforces data integrity through model validation, database relationships, and status state machines.

🏨 rooms.RoomChamber
Represents physical suites. Key fields: title, slug, category (FK), room_number, base_price, discount_price, currency (FK), max_adults, max_children, room_size, total_inventory, tax_percentage.
🏷️ rooms.SeasonalPrice
Dynamic seasonal price overrides for high seasons, festivals, or holidays. Fields: room (FK), name, start_date, end_date, price_override, is_active.
📅 booking.BookingReservation
Central reservation record. Fields: booking_uid (UUID), room (FK), guest_name, guest_email, guest_phone, check_in, check_out, num_rooms, adults, daily_rate, subtotal, tax, total, currency_code, status (draft/pending/confirmed/cancelled).
💳 payments.PaymentTransaction
Audit trail for all checkout attempts. Fields: booking (FK), gateway (stripe/esewa/khalti), transaction_id, amount, currency, status (pending/success/failed), gateway_payload, created_at.

Add-on Pricing Types (rooms.RoomAddon)

Price Type Calculation Formula Use Case
fixed price × quantity One-time services (e.g. VIP Champagne bottle, Flower arrangement)
per_night price × nights × num_rooms Nightly room upgrades (e.g. High-speed executive Wi-Fi, Balcony view)
per_person price × total_guests One-time per-guest services (e.g. Simara airport pick-up shuttle)
per_person_per_night price × total_guests × nights Recurring personal services (e.g. Full-board breakfast buffet)

5.2 Real-Time Availability Checking Logic

The availability endpoint at /rooms/api/<room_id>/check-availability/ checks whether a requested room has enough physical chambers free for the given date range.

Overlapping Date Formula:
Two date ranges [check_in, check_out] and [b.check_in, b.check_out] overlap if and only if:
b.check_in < requested_check_out AND b.check_out > requested_check_in

Only confirmed bookings (and active locked reservations) are counted against the room's total_inventory, preventing false "sold out" states from abandoned cart sessions while guaranteeing zero double-bookings.

6. Multi-Gateway Payment Architecture

Payment processing utilizes the Factory Pattern located in payments/services/. The factory dynamically instantiates the correct service class depending on the chosen provider:

Gateway Currencies Handshake Method Verification Route
Stripe USD, EUR, GBP, AUD Stripe Checkout Session (Redirect URL) Webhook: /payments/webhook/stripe/
Callback: /payments/callback/stripe/
eSewa NPR HMAC-SHA256 Form Post via Base64 Payload Callback: /payments/callback/esewa/
Khalti NPR REST API Session Initiation (pidx) Callback: /payments/callback/khalti/

Stripe Webhook Asynchronous Flow

Endpoint: POST /payments/webhook/stripe/ (CSRF exempt)
Security: The webhook validates the Stripe-Signature header against the configured STRIPE_WEBHOOK_SECRET. When a checkout.session.completed event arrives, it inspects session.metadata.booking_uid, confirms the payment transaction, and flips the booking status to confirmed atomically.

Currency Locking Guarantee

To prevent currency exchange arbitrage between booking initiation and payment processing, the currency selector is automatically locked on the checkout page (checkout.html). If the reservation is in USD, only Stripe is offered. If the reservation is in NPR, local wallets eSewa and Khalti are presented.

7. Frontend Design System & Responsiveness

7.1 Unified Breakpoint Hierarchy

Viewport Category Screen Width Layout Strategy
Mobile < 640px Single column stacked, full-width CTA buttons (w-full sm:w-auto), hamburger drawer navigation, collapsible filter panels.
Tablet 640px – 1024px 2-column grids for cards and form fields, drawer navigation active (lg:hidden) to prevent 8-item menu overflow, sticky booking widgets adapt below hero content.
Desktop > 1024px Full horizontal mega menu, multi-column grids (3–4 columns), sticky sidebar booking reservation cards.

7.2 Smooth Scrolling (Lenis) with Modal Protection

The platform uses Lenis Smooth Inertia Scrolling on desktop and mobile. To prevent background scroll bleed when modals (search, image lightbox, booking guest details, security handshake) are open, a universal MutationObserver halts Lenis scrolling whenever overflow: hidden or modal-open is attached to the <body> element.

7.3 Mobile-First Viewport Typography & Spacing Optimization

To deliver a pristine 5-star guest experience on mobile devices without horizontal overflow or clunky oversized headings, all 11 public-facing template domains implement mobile-first responsive scaling:

  • Tightened Hero Banners & Headings: Section titles scale dynamically (e.g. text-2xl sm:text-5xl lg:text-6xl for page banners; text-xl sm:text-4xl for room chambers and venues).
  • Compact Vertical Spacing: Heavy desktop padding (py-16 sm:py-24) is proportionately reduced on mobile viewports to py-8 sm:py-20.
  • Mobile Navigation Header: The topbar and main navbar reduce height on mobile (h-16 sm:h-20) with a compact logo (h-10 sm:h-14) and dedicated mobile currency badge.
  • Form Inputs & Controls: Buttons, counters, and input fields scale to touch-friendly heights (py-2.5 sm:py-3.5) preventing browser viewport zoom.

7.4 Mobile Bottom Sheet Modal & Responsive Add-on Toggles

On room detail and booking pages (rooms/templates/rooms/room_detail.html):

  • Bottom Sheet Architecture: The draft reservation modal automatically transforms into a native-feeling slide-up bottom sheet on mobile screens (items-end sm:items-center, rounded-t-3xl sm:rounded-2xl, with a centered top drag handle w-10 h-1 bg-neutral-400/50 rounded-full).
  • Smooth Transform Transitions: Powered by Alpine.js, the modal slides up vertically from the bottom on mobile (translate-y-full to translate-y-0) while centering and fading smoothly on tablet and desktop (sm:scale-95 sm:opacity-0).
  • Responsive Add-on Switch Controls: Ancillary service add-ons feature responsive animated toggle switches (w-9 h-5 sm:w-11 sm:h-6 with sliding knob translate-x-4 sm:translate-x-5) with real-time multi-currency price calculations.

11. Operational Runbook & Troubleshooting Guide

Common Operational Issues & Resolutions

Symptom Probable Cause Resolution Procedure
Stripe Webhook Signature Verification Error (400) Mismatched STRIPE_WEBHOOK_SECRET between Stripe Dashboard and .env. Retrieve current signing secret from Stripe Dashboard (Developers > Webhooks) and update .env.
Room Shows Unavailable but Calendar is Empty A draft booking created during testing is locking inventory. Run cleaning command or cancel draft reservations from Django admin.
Static Assets / Styles Missing in Production Static bundle was not collected into staticfiles/ directory. Run python manage.py collectstatic --noinput and check Nginx alias mapping.
Air Datepicker Virtual Keyboard Pops Up on Mobile Input lacks readonly or inputmode="none" attributes. Ensure inputs are initialized via base.html auto-initialization script.
